# CYBER-CAT · MVP 范围

日期：2026-07-29
状态：已与产品负责人逐项确认，作为开发依据。

术语定义见 [CONTEXT.md](../CONTEXT.md)，架构决策见 [docs/adr/](adr/)。
本文只写「做什么、做到什么程度」，不写实现方案。

## 1. 产品形态

常驻桌面宠物，同时支持 macOS 与 Windows，技术栈 Tauri v2（[ADR 0003](adr/0003-desktop-pet-tauri.md)）。
猫生活在用户的真实桌面上，没有虚拟房间（[ADR 0004](adr/0004-desktop-as-territory.md)）。
时间与现实 1:1 流逝，不加速。
MVP 仅在 macOS 上验收，Windows 由外部协作者编译验证。

## 2. 猫

### 2.1 身份

一只猫由「品种 + Seed + 出生时间 + 名字」唯一确定，存档只需存这四项即可完整重建。

七个品种：橘猫、黑猫、奶牛猫、布偶猫、德文卷毛、美短、阿比西尼亚。
品种决定骨架结构与性格倾向，Seed 在品种框架内决定个体差异（花纹、体型、耳尾形状、性格参数）。
性格参数至少包含活跃度、粘人度、贪吃度，由 Seed 在品种倾向附近采样，因此同品种的两只猫行为可以不同。

### 2.2 外观与动画

全部程序化生成，无任何预绘制精灵图（[ADR 0002](adr/0002-procedural-pixel-cats.md)）。
渲染核心 `cat-core.js` 已在 prototype ①② 验收通过，直接复用。
渲染层需额外把每帧的 alpha 掩膜作为公开产物暴露出来，供窗口命中测试使用（[ADR 0006](adr/0006-alpha-mask-hit-testing.md)）。

动作库（已实现并验收）：站立呼吸、走路、坐下、趴下、睡觉、舔毛、吃饭、打哈欠、伸懒腰、扑跳。
微动作层（已实现并验收）：随机眨眼、耳朵抖动、偶尔歪头、尾巴摆动、呼吸起伏。
微动作层必须能独立开关且与基础动作正交，不要把微动作烧进动作定义里。
桌面宠物形态需**新增**的动作：跳上高处、从高处跳下、在窄边缘行走（走窗口上沿用）。

**外观与动画的具体结论是约束，不是建议**：品种辨识特征、花纹算法、动作节奏等都经过多轮验收，且每条都有被明确否决的前任方案。
见 [art-and-motion-decisions.md](art-and-motion-decisions.md)。重构渲染代码前必读，否则很容易把已否决的方案当成改进重新引入。

### 2.3 生命模拟

三条需求随时间演化：饱食度、精力、心情。
另有亲密度，由所有互动长期累积，长期不互动会缓慢流失。

数值节奏（**已定档**，2026-07-29 产品负责人确认；源自 prototype ④ 的实测设定，模拟步长 30 分钟）：

| 项目 | 数值 |
|---|---|
| 饱食度 满 → 空 | 约 16 小时（一天喂 1 到 2 次） |
| 空腹持续 → 生病 | 24 小时 |
| 生病 → 死亡 | 48 小时 |
| 最后一次喂食 → 死亡 | 约 3.7 天 |

这些值仍应实现为集中的命名常量而非散落的字面量 - 定档指的是不再等待产品决策，不是禁止后续调优。

生病是死亡的必经前置状态，猫不会跳过生病直接死亡。
生病有明确可视表现（蔫、趴着不动），喂药可治愈。
死亡不可逆，以安静的告别页呈现，旧猫进入猫的档案，之后可无惩罚地领养新猫。

作息遵循真实猫的晨昏型节律：黎明黄昏活跃，白天大睡，深夜偶发跑酷。
昼夜跟随系统时钟，但 MVP 不做任何昼夜画面表现（场景已废弃），只影响猫的行为。

模拟器必须是确定性纯函数（[ADR 0001](adr/0001-offline-catchup-simulation.md)）：输入快照与时间差，输出当前状态与期间事件列表。
应用常驻期间猫真的在逐 tick 运行；关机或睡眠期间靠离线推演补算。

## 3. 五个 MVP 特效

按实现优先级排列，全部进 MVP。

### 3.1 猫爬到前台窗口上

读取当前前台窗口的位置与尺寸，猫沿其上边缘行走，或趴在标题栏上。
这是桌面宠物形态的核心价值体现，优先级最高。

技术路径已确认可行且**两个平台都不需要任何用户授权**（[ADR 0005](adr/0005-window-geometry-without-permission.md)，实测证据见 [调研文档](research/2026-07-29-window-position-apis.md)）。
因此 MVP 不需要权限引导流程，也不需要降级模式。

实现要点（两个平台都已实机验证，数据见调研文档）：
- macOS 用 `NSWorkspace.frontmostApplication` + `CGWindowListCopyWindowInfo`，过滤 `kCGWindowLayer == 0` 并排除宠物自身 PID。稳态下只查已锁定的 windowID，不做全量枚举。
- Windows 用 `GetForegroundWindow` + `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`，**不能用 `GetWindowRect`** - 最大化窗口下它的顶边比可见顶边高 11 像素，猫会浮空。
- Windows 若后续引入 `EnumWindows`，必须查 `DWMWA_CLOAKED` 并排除非 0 的窗口，否则会拿到 DWM 隐藏的内部窗口（「设置」应用实测存在同标题的 cloaked 窗口）。
- **猫的贴图必须按目标窗口所在显示器的 DPI 缩放。** 同一窗口跨不同缩放的显示器时物理尺寸会变（实测 900×650 @150% → 600×433 @100%），不缩放猫就会与窗口比例失配。macOS 用 `backingScaleFactor`，Windows 用 `GetDpiForWindow`。
- 坐标系差异：macOS 的 `kCGWindowBounds` 是点，直接当 `LogicalPosition`；Windows 在 Tauri 默认的 PMv2 下是物理像素（跨屏统一、左侧屏为负值），走 `PhysicalPosition`。
- 轮询默认 10 Hz，猫静止时降到 2 Hz，睡眠与锁屏时停止。开销实测：macOS 增量查询 0.072 ms，Windows 三个调用合计约 0.076 ms。

### 3.2 光标即逗猫棒

光标天然充当逗猫棒，无任何开关或按钮。
必须通过下面六道闸门，任何一道不满足则完全无视光标：

1. **状态闸门** - 睡着、生病、刚吃饱犯困、心情很差时无反应。
2. **距离闸门** - 光标需进入猫的注意范围（约 150 到 200 像素）。
3. **运动特征闸门** - 只有速度快且方向多变的「像猎物」的运动才算邀请；匀速直线移动视为用户正常操作，不触发。
4. **打字免打扰** - 键盘活跃期间完全无视光标。
5. **玩腻机制** - 连续扑中 3 到 4 次后失去兴趣，进入数分钟冷却。
6. **全局节流** - 每小时主动追逐次数有上限，活跃度高的猫上限更高。

另有两条细节要求：
猫扑向光标的**邻近落点**而非光标本身，扑完停在侧面，不得压在用户要点击的位置上。
以上所有阈值必须做成可调配置，开发期取保守值，真机使用数天后再定档。

### 3.3 拖拽猫

可以抓起猫拎到桌面别处。
落地反应体现性格：粘人的猫立刻蹭回光标边，高冷的猫走开去别处趴下，共通表现是甩尾巴表示不满。

### 3.4 托盘图标即状态显示

托盘图标本身反映猫的当前总体状态（正常、睡着、饿了、生病），不打开任何窗口即可知晓。
四条需求的详细数值放在托盘菜单里展开查看。

### 3.5 爪印

猫走过的位置留下几秒钟即淡去的小爪印，经过前台窗口时尤其明显。

## 4. 交互清单

| 交互 | 入口 | 猫的响应原则 |
|---|---|---|
| 添粮 | 点击食盆挂件；托盘菜单亦有快捷项 | 邀请式：贪吃的立刻冲来，不饿的晚点再说，睡着的可能睡完这觉 |
| 抚摸 | 点击猫 | 醒着时蹭手心并冒爱心；睡着时甩尾巴表示不满 |
| 拖拽 | 按住猫拖动 | 见 3.3 |

「点击猫」与「拖拽猫」依赖 alpha 掩膜命中测试才能与桌面穿透共存，见 [ADR 0006](adr/0006-alpha-mask-hit-testing.md)。
| 逗猫 | 移动光标 | 见 3.2 的六道闸门 |
| 喂药 | 托盘菜单，仅生病时出现 | 立即生效，治愈后有数小时病后虚弱 |

所有交互遵循邀请式原则：只影响环境或发出邀请，猫保有自主决定权。

## 5. 桌面挂件

MVP 两个，各为独立的透明小窗口，位置由用户拖动决定，均可隐藏。

- **食盆** - 喂食主入口，点击添粮。猫走向食盆的过程本身是内容。
- **猫窝** - 猫困了会走回猫窝睡，而不是随地趴下。

挂件数量必须克制，避免变成桌面垃圾。

## 6. 托盘菜单

- 猫咪日记
- 四条需求状态详情
- 喂食（快捷项）
- 喂药（仅生病时出现）
- 安静模式开关
- 退出

**安静模式**是所有主动行为的统一兜底：开启后猫只趴着休息，不响应光标，不爬前台窗口。

## 7. 需要窗口的两个一次性流程

均为小尺寸居中窗口，用完即关，不常驻。

**领养起名** - 首次启动。猫从雨夜里走来并停下，用户可以让它再等等（重新抽取），直到遇到想留下的那只，然后为它命名。
措辞与呈现强调猫是主动到来的个体，不是被生成或购买的。

**告别页** - 猫死后。展示陪伴天数、喂食次数、抚摸次数，可翻看它的一生日记，然后送别并领养新猫。
内含猫的档案：养过的所有猫的列表。

## 8. 已完成的验证与仍未知的风险

### 已验证：窗口几何读取（特效 3.1 的技术底座）

**macOS 与 Windows 均不需要任何用户授权，两个平台都已实机验证。**
macOS 在本机 15.5 实测，Windows 由外部协作者在 11 25H2（build 26200.8875）双显示器混合 DPI 环境实测。
包括管理员权限窗口、UWP 打包应用、负坐标、跨 DPI 尺寸变化、性能开销。
详见 [ADR 0005](adr/0005-window-geometry-without-permission.md) 与 [调研文档](research/2026-07-29-window-position-apis.md)。

### 已验证：宠物自身的透明置顶窗口（Windows）

2026-07-29 由协作者用 Electron 在 Windows 11 25H2 双屏混合 DPI 环境代跑验证。
用 Electron 而非 Tauri 是因为协作者无 Rust 工具链；这几项测的是 Win32 窗口样式与 Chromium 渲染行为而非框架特性，因此结论可迁移。
完整报告与证据（截图、录屏）见 [research/2026-07-29-windows-transparent-window/](research/2026-07-29-windows-transparent-window/report.md)。

**结论：Windows 上做透明像素风桌面宠物没有阻断级障碍。**

通过项：
- 透明边缘干净，纯黑背景上看不出任何白边或窗口轮廓，也没有额外的不可见外边距。
- `hasShadow:false` 生效，无阴影；可见内容的直角未被系统裁圆。
- `skipTaskbar` 生效：任务栏、Alt+Tab、Win+Tab 都没有该窗口的入口。
- `screen-saver` 置顶层级能覆盖全屏视频播放器与 PowerPoint 全屏演示者视图。
- **像素画在 150% 缩放屏上保持锐利**（每源像素稳定占 6×6 物理像素，截图中只有 3 种绘制色、无插值中间色），`image-rendering: pixelated` 确实生效。美术方向成立。

发现的两条硬约束，已分别落为决策：
- **透明像素不自动穿透，且穿透 API 是整窗一刀切** → 见 [ADR 0006](adr/0006-alpha-mask-hit-testing.md)。
- **跨 DPI 边界时窗口物理尺寸会瞬间跳变**（603×453 @150% → 402×302 @100%，逻辑尺寸不变），用户能看到猫「跳一下」。无白帧、无持续模糊，但需要设计跨屏移动的视觉过渡策略。

由此新增的一条实现约束：**Canvas 的 CSS 放大倍数必须使 `cssScale × devicePixelRatio` 为整数**，否则单个源像素会落在非整数个物理像素上，出现宽度不一的像素块。实测的 4×1.5=6 与 4×1=4 都是整数所以锐利；若取 3×1.5=4.5 就会破功。更稳妥的做法是直接按物理分辨率渲染 Canvas。

### 已验证：macOS 侧宠物窗口的点击穿透

2026-07-29 实测（[报告](research/2026-07-29-macos-hit-test/report.md)）。
结论与 Windows 一致，ADR 0006 成立，但根因是 **WKWebView 无条件截获整个窗口**而非窗口本身 - macOS 的窗口层其实原生支持逐像素 alpha 穿透。
新增一条实现约束：macOS 上动态开关有最长约 5ms 传播延迟，必须提前于光标抵达切换并带外扩边距，不能在 `mouseDown` 里现场切换。

### 仍未知
- 启动白闪与 `noRedirectionBitmap` 的实际效果 - Electron 启动路径不可迁移，须等真机 Tauri 构建。
- 真实全屏游戏、受保护视频、会议软件屏幕共享下的置顶行为。MVP 的「让开」规则（第 9 节）本就要求这些场景下隐藏，风险可控。
- Windows 11 是否对透明无边框窗口的外框施加强制圆角 - 因外框完全不可见，无从观测，实际上不构成问题。
- 真实全屏游戏与全屏视频下 `GetForegroundWindow` 的行为。

## 9. 明确不做

- **拦截键盘或鼠标输入。** 挡视线可以，挡操作不行。
- **把桌面图标推下桌。** 猫感十足，但用户第一反应是文件丢了，惊吓大于乐趣。
- **默认开启声音。** 咕噜与喵叫可以有，默认必须静音。
- **频繁系统通知。** 只有生病这一级才发通知，饿了不发，否则产品气质从陪伴变成催促。
- **虚拟房间与场景美术。** 已随 ADR 0004 废弃。

另需一条「让开」规则：检测到全屏应用或投屏演示时猫自动隐藏。

## 10. MVP 后再考虑

多场景、多猫、装扮、雨声与环境音、猫毛与更多桌面痕迹、深夜劝睡、多显示器穿越、系统状态（CPU、音乐）驱动的猫反应、挠下巴与逆毛摸等精细触摸交互、开关机进出场动画。
