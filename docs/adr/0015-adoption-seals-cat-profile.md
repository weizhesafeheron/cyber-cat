# 0015 - 领养封存猫咪档案，品种使用目录与花纹适配器

日期：2026-07-30
状态：已采纳

## 背景

旧身份模型用「品种 + Seed」同时重建外观和性格。它适合第一版的随机领养，却有三个限制：

- 用户无法留下性格不变、只调整形象或动作；
- 语义美术参数只能放在内部工作台，产品流程消费不到；
- 新增品种需要同时修改类型联合、生成分支和着色分支，品种数量越多越难维护。

领养仍应读成一次相遇，而不是运行期角色编辑器。猫回家之后持续存在，不能随时被改成另一只。

## 决策

领养开始时独立随机一次性格。用户可以在同一窗口选择品种、切换花纹模板、调整语义形象参数，并为每个动作调整视觉风格。花纹拥有独立 Seed，切换花纹不会改变已经选定的形体。

确认并命名后，存档封存一份猫咪档案：

- 品种 ID 与形体 Seed；
- 花纹适配器内的模板 ID 与独立花纹 Seed；
- 独立性格；
- 形象参数；
- 用户改过的逐动作参数；
- 名字与出生时间。

运行期只有读取接口，没有编辑档案的命令。死亡后重新领养会创建新档案。旧存档没有这些字段时继续走原来的「品种 + Seed」重建路径，保证已有的猫不变。

品种改为数据目录。每份品种数据声明骨架参数、调色板和 `markingAdapter`；每个适配器声明自己的稳定模板集合，渲染器按花纹适配器与模板分派生成和着色算法，不识别品种 ID。复用已有花纹语言的新品种只增加目录数据，新的花纹语言才增加一个适配器。

## 理由

- 性格、形体与花纹拥有不同随机源，换花纹不会暗中换掉体型或“它是谁”；
- 语义参数既适合人拖滑块，也适合 AI 把自然语言或参考图转换成安全候选；
- 封存保持长期陪伴的身份连续性，避免运行期编辑破坏日记、回忆与死亡档案；
- 目录 + 适配器把“新增品种”和“发明新花纹算法”分开，成本随真正的新能力增长。

## 后果

- 世界存档和猫的档案会保存少量不可重建的个体参数，`makeCat(breed, seed)` 不再是新身份的全部真相；
- 花纹模板 ID 是持久化协议；发布后的模板不可改名，只能新增或兼容迁移；
- 动作调参只作用于渲染姿态，不改变世界层动作选择、移动目标或需求演化；
- 跨窗口领养载荷变大，并必须逐字段校验；
- 新品种仍需一份程序化调色板和骨架数据，但不再修改封闭类型与品种 `switch`；
- 独特、难以程序化的复杂外观仍可能需要新的花纹适配器，程序化渲染决策本身不变（ADR 0002）。

## 被否决的方案

- **保留独立工作台，再手工复制 JSON 到正式环境**：产品领养流程无法直接受益，且复制会产生两份真相。
- **回家后随时编辑**：破坏“领养的是同一只猫”的身份连续性。
- **性格继续由品种 + Seed 决定**：换外观会暗中重抽行为，不符合用户预期。
- **把每个品种写成独立渲染分支**：新增相似品种也要修改核心代码，扩展成本与回归面过大。
