# 0011 - 回归气泡是舞台里的覆盖层，命中区是一个矩形

日期：2026-07-29
状态：已废弃（2026-08-03）

> 回归气泡已移除。新日志改由托盘菜单「猫咪日记」后的持久未读圆点提示，
> 打开日记后清除。本文保留为历史决策记录，不再描述当前实现。

## 背景

「离开超过阈值（约 2h）后重新启动，猫头顶冒一个**可点的**小气泡，点开才展开日记」
（[CONTEXT.md](../../CONTEXT.md) 的猫咪日记、[ADR 0004](0004-desktop-as-territory.md) 把它从弹窗改成气泡）。

三条既有约束同时压在这个小东西上：

1. **精灵缓冲里只有猫。**（[art-and-motion-decisions](../art-and-motion-decisions.md) 的「场景道具一律不画在精灵缓冲里」，[props/art.ts](../../src/props/art.ts) 复述了一遍。）
   缓冲里的每个像素都会进描边通道与命中掩膜，画进去等于让猫的可点范围长出一块。
2. **只有猫本体的像素算命中**（[ADR 0006](0006-alpha-mask-hit-testing.md)）。
   穿透是整窗一刀切的，判定层不认识的东西就点不动。
3. **气泡要跟着猫头顶走**，而猫在舞台里逐帧移动，位置由运动层持有（[ADR 0007](0007-stage-window-and-motion-layer.md)）。

## 决策

### 一、气泡是舞台里的第三张画布，不是独立窗口、也不画进精灵缓冲

走爪印那条路（[app/paws.ts](../../src/app/paws.ts)）：铺满舞台、盖在猫之上、`pointer-events: none`。

**位置用精灵坐标表达**（相对精灵左上角，y 为负 = 在 72×56 那个缓冲之上）。
这一条是关键：猫的画布靠 `transform` 在舞台里移动，气泡按同一个 `display.originCss` 换算，
于是「跟着猫头顶走」是结构保证的 - 没有任何逐帧跟随的代码，也就不会与猫脱节。

气泡下沿钉在精灵第 5 行。这个数是量出来的：七个品种 × 五颗种子 × 全部动作逐帧渲染，
猫本体最靠上的像素落在第 7 行（扑跳腾空那一帧），留两行空隙。
**被否决的方案是「跟着渲染层的头部锚点走」** - 锚点每帧都在动，气泡会跟着抖；
而且趴下、睡觉、吃饭时头会低到第 21 行，气泡跟下去就钻进猫身上了。

### 二、气泡的命中区是一个矩形，与掩膜取并集

判定层（[app/hit.ts](../../src/app/hit.ts)）新增 `HitRect`，`HitInput.rects` 每帧传入当前该有的矩形。
掩膜与矩形是并集：猫可点，气泡也可点。

ADR 0006 否决过「静态矩形热区」，但那是**针对猫**的：猫的姿态差异极大，
单一矩形要么漏身体要么覆盖大片空白。气泡本身就是一张固定尺寸的矩形贴图，
矩形是它的精确形状而不是近似，那条否决在这里不适用。
代价是四个圆角（各 2×2 像素）也算命中 - 比为一张 22×18 的贴图再维护一份掩膜通道划算。

### 三、「离开了多久」由启动时的离线补算给出，渲染层不读时钟

判定写成纯函数 `shouldOfferDiary({ awayMs, since, diary, dead })`，
由 `main.ts` 的 `catchUp` 调一次 - 那里本来就知道补算了多少毫秒。

三个条件都要成立才冒气泡：离开超过阈值、**离开期间真的产生了日记**、猫还在。
第二条是必需的：补算了六小时却一条没记（猫整夜在睡且抽签都没中）时冒气泡，
用户点开只会看到旧内容，比不提示更糟。第三条把死掉的猫让给告别页（ticket 13）。

**气泡三分钟后自己收掉。** 它是一块 66×54 CSS 像素的可点区域，跟着猫在整个桌面上走；
不设期限的话，用户不理它就等于在猫头顶留了一块永久偷点击的区域。
「不拦用户」这条要求包含「不理它它就该消失」。错过了也没关系 - 日记的常驻入口在托盘菜单，
气泡只是提示。寿命用帧时钟（`performance.now`）计，和爪印、点猫的即时反馈同一族。

### 四、舞台高度从 200 提到 240

气泡需要 14 个精灵像素的净空，在最坏缩放下是 47 CSS 像素。
猫的精灵缓冲里放不下它：顶部只有 7 行是空的（见上面量出来的第 7 行），
那只够 21 个物理像素，气泡会小到点不中。

### 五、日记窗口按需建、用完即关，自己读存档

与领养窗口同一个模式（[src-tauri/src/diary.rs](../../src-tauri/src/diary.rs)），不写进 `tauri.conf.json` 的 windows。
托盘菜单的「猫咪日记」与气泡共用同一条命令。

日记页**自己去读存档文件**，宠物窗口不推状态给它。
理由是宠物窗口每产生一条事件就会立刻存盘，所以文件里的日记从不落后；
而推送方案要多一套 ready / sync 握手（挂件那边就是这么做的，因为它要显示实时份数），
为一页只读的东西引入握手只是多一处能不一致的地方。
代价是日记开着的时候不会自己刷新 - 用户是来翻看的，不是来盯着的。

## 理由

**为什么不做独立的气泡窗口。** 气泡要贴着猫的头顶，而猫每帧都在动；
独立窗口意味着每帧一次跨进程的窗口移动，正是 ADR 0007 里带滞后要避免的开销，
而且窗口位置与画布偏移之间必然差一帧，气泡会跟着猫抖。

**为什么文案不进存档。** 同一件事对懒猫和活跃猫要说成不同的话，而性格由「品种 + Seed」重建。
文案存进去就锁死了：之后改一个字，老存档里的旧句子会和新句子混在一起，而且再也调不动。
所以渲染是纯函数 `(event, cat) -> string`（[src/diary/text.ts](../../src/diary/text.ts)），存档里只有结构化事件。

## 影响

- 舞台的透明区变大约 20%，而穿透是整窗一刀切的。接受它：判定的失效方向是「一律穿透」，
  变大的只是误判窗口期里可能挡住的面积。
- `PassthroughController.update` 多了一个可选的 `rects` 参数。挂件窗口不传，行为不变。
- 气泡的矩形**每帧算一次，画和判用同一个值**。分成两份迟早差一像素，
  症状是「看起来点在气泡上但没反应」，在真机之外看不出来。
- `docs/adr/0006` 的「只有猫本体算命中」现在要读成「猫本体 + 显式声明的 UI 命中区」。
  再加第二块这样的区域之前，先想清楚它能不能用掩膜表达。
- 一条**没有被这一版满足**的验收标准：「懒猫的日记以睡觉为主，活跃猫鸡飞狗跳」
  在**措辞**上成立（有测试，见下），在**事件构成**上基本不成立 -
  日记记的是状态转换而不是时长，而转换次数几乎不随活跃度变化（懒猫睡得更久，
  但也醒得更频繁，两头抵消）。实测 14 只懒猫与 14 只活跃猫的题材占比几乎相同。
  真正随性格变的事件构成来自**贪吃度**（`ateGreedy` 只有贪吃猫会产出）。
  要让活跃度也影响构成，得改世界层：把 `ZOOMIES_EVENT_CHANCE` 与日常小事的抽签按
  `active` 加权，或者让日记记「睡了多久」而不只是「睡下了」。那属于世界层的调参，
  不在本 ticket 内。
