# 0006 - 用 alpha 掩膜逐帧命中测试实现「猫身上可点、其余穿透」

日期：2026-07-29
状态：已采纳

## 背景

桌面宠物的窗口是一个透明无边框窗口，只有猫本体是不透明像素，其余全是透明区。
理想行为是：点猫有反应，点猫以外的透明区域则穿透到用户真正在操作的窗口。

Windows 实机实测（[报告](../research/2026-07-29-windows-transparent-window/report.md)）否定了两个想当然的假设：

1. **透明像素不会自动穿透。** 默认状态下，窗口会截获落在完全透明区域上的点击，下层窗口收不到。也就是说一个 400×300 的宠物窗口会在用户桌面上挖出一块 400×300 的死区。
2. **`setIgnoreCursorEvents` 是整窗一刀切。** 开启后连猫本体都不可点；Electron 的 `{forward: true}` 只额外转发 `mousemove`，不恢复区域点击。实测 Win32 扩展样式确认开启后窗口带上了 `WS_EX_TRANSPARENT`。

macOS 侧机制相同（`NSWindow.ignoresMouseEvents` 同样是整窗属性，透明视图仍占据其 frame 并接收点击），因此这不是 Windows 特有问题，而是两个平台共有的约束。
**macOS 侧尚未实机验证，但设计上按同样约束处理。**

## 决策

**逐帧维护猫的 alpha 掩膜，用光标位置对掩膜做精确命中测试，据此动态开关整窗穿透。**

- 命中猫的不透明像素 → 关闭穿透，窗口可接收点击（抚摸、拖拽）。
- 未命中 → 开启穿透，点击落到下层窗口。
- 窗口尺寸尽量贴合猫的包围盒，缩小透明死区，降低误判窗口期的影响。
- Windows 上优先改用原生 `WM_NCHITTEST` 或窗口 region 做命中测试，以消除轮询竞争；轮询版本仅作为初期实现。

## 理由

掩膜对本项目是**免费的**。
猫是我们自己逐像素程序化渲染的（[ADR 0002](0002-procedural-pixel-cats.md)），渲染缓冲区里每个像素是否不透明本来就是已知信息，不需要额外的碰撞形状或手工标注的热区。
这比「用一个静态矩形近似猫」精确得多，也比「整窗可点」对用户友好得多。

被否决的备选：

- **整窗可点**：在用户桌面上挖一块死区，不可接受。
- **整窗穿透**：猫彻底不可交互，「点猫抚摸」与「拖拽猫」两个 MVP 交互直接失效。
- **静态矩形热区**：猫的姿态差异很大（伸懒腰横向拉长、蜷睡缩成一团、扑跳腾空），单一矩形要么漏掉身体要么覆盖大片空白。

代价是引入了一个每帧的命中测试与穿透状态切换，且轮询实现在鼠标快速穿越边缘时存在竞争窗口。
协作者实测确认轮询方案（25 ms 间隔）可用，但建议生产实现走原生命中测试 - 采纳该建议。

## 影响

- 渲染层必须把 alpha 掩膜作为公开产物暴露给窗口层，而不只是画到 canvas 上。
- 命中形状必须与动画帧同步，不能用上一帧的掩膜判断当前帧。
- 「光标即逗猫棒」（[MVP 特效 3.2](../mvp-scope.md)）依赖持续获取光标位置，与本方案共用同一套光标追踪，实现上应合并为一处。
- macOS 侧的实际穿透行为需在开发早期验证，若与预期不符需要单独设计降级方案。
