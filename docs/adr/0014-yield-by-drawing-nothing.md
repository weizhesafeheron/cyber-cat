# 0014 - 让开规则用「什么都不画」实现，不隐藏宠物窗口

日期：2026-07-30
状态：已采纳

## 背景

「检测到全屏应用或投屏演示时猫自动隐藏，退出该状态后恢复」（issue #15）。
产品口径是**用户永远优先**（ADR 0004）：桌面是猫的领地，但别人在放片、在做演示的时候，那只猫必须消失。

同一张票上还有一条看起来无关的验收项：**「隐藏与恢复期间猫的状态继续正常推演，不丢失」**。
这两条放在一起，决定了「隐藏」不能按字面理解。

## 决策

宠物窗口**不隐藏**。让开期间做三件事：

1. 把所有画布擦掉（`blank()`），窗口留着，全透明。
2. 强制打开整窗点击穿透（`passthrough.yieldTo(true)`）。
3. 食盆与猫窝**是真的隐藏**（`PropsHost.suppress(true)`）。

### 为什么不能 `window.hide()`

**`requestAnimationFrame` 对隐藏窗口不触发。** 帧循环是这个应用的心脏：世界推演、存档、托盘刷新、以及「该不该让开」的轮询全都挂在上面。真把宠物窗口隐藏掉，帧循环就停了，于是**再也没有人来问「全屏退出了吗」** - 猫一去不回。

这个坑在启动流程上已经踩过两次（见 `lib.rs` 的 `content_ready`：把「通知显示窗口」放进 rAF 回调会死锁在「窗口永远不出现」上）。让开规则是第三次遇到同一个约束，只是这次的症状更隐蔽 - 它要等到用户退出全屏才暴露。

要走隐藏那条路，就得在 Rust 侧另起一个定时器来轮询并唤醒窗口，即在帧循环之外再造一套生命周期。为一个视觉效果引入第二个时钟源不值得。

### 为什么挂件可以真的隐藏

它们是独立窗口，**不驱动任何循环**：位置与显隐都由宠物窗口下发（`place_prop`）。宠物窗口的帧循环还活着，所以随时能把它们放回来。

隐藏挂件时**不动用户记的显隐状态**：那是他在托盘里勾的，属于偏好；让开是「此刻别人在演示」。混成一个字段的话，一场全屏视频会把用户主动藏起来的猫窝重新显示出来。代价是去重要比「实际下发的那份」而不是「存档里的那份」，否则解除让开时会被判成「没变」而不补发，挂件再也回不来 - 这条有测试守着。

### 顺带解决的两件事

- **状态继续推演成了结构保证**，而不是靠离线追平补救：帧循环还在跑，世界每帧照常 `step`，存档与托盘照常刷新（周期性事务抽成 `housekeeping`，让开那条路也走它）。一场两小时的全屏演示期间一次都不落盘的话，中途关机就全丢了。
- **穿透必须强制打开**：桌面上那块什么都没画的透明窗口绝不能截获点击。用户正在全屏演示，一块看不见的死区正是这条规则要防的事情本身。

### 告别页刻意不在让开期间弹

猫死了要弹告别页，而那是一扇会抢焦点的窗口 - 盖在别人的演示上是这条规则最不能接受的失败。
`farewell.observe` 是幂等的，让开期间跳过它只是推迟到猫回来那一帧，不会漏。

生病的系统通知照发：系统自己会在全屏时压住通知，那是用户在系统设置里的选择，不该由我们代劳。

## 后果

- 全屏期间仍有一个 60 Hz 的空帧循环在跑。它只做世界推演与几次节流判断，不画任何东西，代价可以接受；换来的是恢复只差一个轮询间隔（1 秒）。
- 「猫藏起来了」在代码里没有一个统一的开关，而是三处协作。因此两个兜底（安静模式与让开）合成一张真值表（`src/app/restraint.ts`）在所有主动行为之前算一次 - 散在帧循环里各写一个 `if` 的话，漏掉一处就没有任何测试碰得到。
- **检测本身是两条启发式信号**（macOS：前台窗口盖满某块显示器、`CGDisplayIsInMirrorSet`），已知的漏判写在 `platform.rs` 的注释里。漏判方向一律是「猫照常出现」- 一只永远不出现的猫会被当成程序坏了，而一只在全屏视频上多待一会儿的猫只是有点烦。

## 被否决的方案

- **`window.hide()` + Rust 侧定时器唤醒**：见上，多一个时钟源。
- **把窗口挪到屏幕外**：等于让猫在别的显示器上乱跑，多屏用户会在副屏看到它。
- **设窗口透明度为 0**：Tauri 2.11 的 `WebviewWindow` 没有这个能力，只能自己写平台代码去设 `NSWindow.alphaValue`，而收益与「不画」完全相同。
- **让世界层知道「现在该让开」**：那会毁掉离线推演的等价性（ADR 0001）- 它不是时间的函数。安静模式同理，两者都只活在应用层。
