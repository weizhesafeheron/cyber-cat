# 0004 - 废弃虚拟场景，用户的真实桌面就是猫的领地

日期：2026-07-29
状态：已采纳（废弃 prototype ③ 已验收通过的「赛博公寓一角」场景）

## 背景

产品形态改为桌面宠物后（见 ADR 0003），出现了一个二选一：
猫要么继续住在一个虚拟房间里（房间作为一个可唤出的窗口），要么直接住在用户真实的桌面上。

前者能保住 prototype ③ 已经验收通过的全部场景工作（赛博雨夜窗景、霓虹招牌、沙发、地毯、猫窝、悬浮猫抓柱）。
后者要把这些资产删掉重来。

## 决策

**取消虚拟房间，猫直接生活在用户的真实桌面上。**

- 猫的落脚点全部来自真实桌面元素：屏幕底边、程序坞/任务栏、当前前台窗口的上边缘。
- 房间里值得留下的道具变成**桌面挂件**：食盆与猫窝各自是一个独立的透明小窗口，位置由用户拖动决定。
- 状态与信息出口收敛到**托盘图标与托盘菜单**，不再有常驻的游戏 HUD。
- 仅保留两个一次性窗口：领养起名与告别页（含猫的档案）。

## 理由

- 桌面宠物的核心价值是「猫在你真的电脑里」，一个虚拟房间会把猫重新关回盒子，等于花了桌面宠物的成本却只拿到网页版的体验。
- 挂件方案让用户在自己的真实桌面上布置猫的领地，这个「安家」感强于任何虚拟房间，因为那是用户每天都在看的桌面。
- 喂食因此从一个菜单项变成空间行为：点食盆添粮，猫自己走过去，走路动画在这里才有意义。
- 代价是明确的：prototype ③ 的场景美术与昼夜氛围系统作废。接受这个代价，因为它换来的是形态本身的价值。

## 影响

- 世界观载体从「场景」转移到猫本身与文案（领养的雨夜、日记的措辞）。赛博朋克氛围不再由背景画面承担。
- 「窗台可跳上去趴着 / 更多家具 / 霓虹招牌带字」这三条原 MVP 场景需求随场景一并作废，其中「跳上高处趴着」的行为价值由「爬到前台窗口上」继承。
- 昼夜同步不再有画面表现，只保留对猫作息的影响。
- 回归日记不弹窗打断用户；当前实现用托盘菜单后的未读圆点提示（旧的头顶气泡已废弃，见 ADR 0011）。
