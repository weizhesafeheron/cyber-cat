# 0013 - 三扇弹出窗口自绘标题栏，不用系统的

日期：2026-07-30
状态：已采纳

## 背景

领养、日记、告别三扇弹出窗口原来用的是系统标题栏。
真机上的观感问题很具体：macOS 那条灰色渐变条 + 系统字体的标题，压在领养页深蓝色的雨夜画面上面，是整页唯一一处与配色断开的地方。

给出了四个方案让用户挑（`.lavish/window-chrome-options.html`）：

| | 做法 | 代价 |
|---|---|---|
| A | 保持现状 | 就是那个「有点丑」 |
| B | `titleBarStyle: Transparent` + `hiddenTitle` | 只有 macOS 有效，Windows 上仍是系统标题栏 |
| C | `decorations: false`，标题条自己画 | 拖动、缩放、关闭全要自己接 |
| D | `decorations: false`，什么都不画 | 领养页失去可见的关闭入口 |

用户选了 **C**（连「日记页留 B」的混合方案也没要）。
理由是像素风要贯彻到底，而且两个平台长得一样。

## 决策

三扇窗口一律 `decorations(false)`，标题条由前端画（`src/chrome/`）：28 像素高的深色窄条，左边一枚像素爪印，中间标题，右边一个自绘的关闭按钮，整扇窗外面一圈 1 像素边框。

四条实现选择：

### 一、标题文字取 `document.title`，不再传第三份

每个页面的 `<title>` 已经写着它，Rust 建窗时也写了同一句。
条子上再写一份的话，三份里必然有一份先对不上。

### 二、拖动用 `data-tauri-drag-region`，不自己算位移

那是系统的窗口拖拽，自带贴边与跨屏，一次拖动只有一次跨进程调用。
它需要 `core:window:allow-start-dragging`，而**这条不在 `core:window:default` 里面**（`tauri-2.11.5/permissions/window/autogenerated/reference.md` 的默认集里没有它）- 漏了它的症状是标题条按下去毫无反应，只在真机上看得见。
所以单独一份 capability（`chrome.json`），只给这三扇窗口，不给宠物窗口 - 那扇窗口整窗穿透，从不接受拖动。

`drag.js` 对 `BUTTON` 有专门的判定（可点击元素默认挡住拖动），所以关闭按钮不需要额外声明 `data-tauri-drag-region="false"`。

### 三、缩放自己算，不用 `startResizeDragging`

**这是这次唯一一个平台事实驱动的决定。**

- macOS：无边框窗口仍然带 `NSWindowStyleMask::Resizable`（tao 0.35 `platform_impl/macos/window.rs:216`），四边其实能拖。
- Windows：tao 给无边框窗口**摘掉 `WS_THICKFRAME`**（`platform_impl/windows/window_state.rs:307`），而 `WS_THICKFRAME` 正是 `DefWindowProc` 执行缩放循环的前提。少了它四边拖不动，Tauri 的 `startResizeDragging` 也一样没反应 - 它做的事就是往窗口投一条 `WM_NCLBUTTONDOWN`/`HTBOTTOMRIGHT`（tao `windows/window.rs:997`）。

所以日记页右下角那个把手是**唯一**的缩放入口，并且必须自己实现：前端按指针位移算出新尺寸，落到应用自己的命令上（`resize_self`）。与挂件拖拽同一条做法。

位移一律用屏幕坐标算。用客户区坐标会形成「窗口变大 → 客户区坐标变小 → 又算出更大的窗口」的正反馈，表现为一拖就飞出屏幕。

### 四、关闭按钮的语义由页面给，三扇各不相同

| 窗口 | 点叉之后 |
|---|---|
| 领养 | **放弃领养**。走新的 `cancel_adoption`，与 `close_adoption` 的区别是不立 `AdoptionDone` 那面旗子 - 旗子的含义是「领养走完了」，用它关窗会让应用以为已经有猫，首次启动时留下一个没有猫的空进程。 |
| 日记 | `close_diary`。Esc 也是同一条。 |
| 告别 | `close_farewell`。不退出应用（那一页是「再养一只」的唯一入口）。 |

## 后果

- **窗口高度全部要加一条标题条**（`withChrome()`）。无边框窗口的客户区就是整扇窗，不加的话内容被压掉 28 像素，而领养页 `overflow: hidden`，被压掉的正好是最后那行提示。三处调用漏掉任何一处都只在真机上看得见，所以有一条测试守着（`test/chrome/chrome.test.ts`）。
- **28 这个数只有一份**（`src/chrome/constants.ts`）：CSS 用 `var(--chrome-h)`，由 `mountChrome` 写进去；日记的尺寸下限也是从这里加出来的，并一路传给 Rust 的 `min_inner_size`（`open_diary` 因此多了两个参数）。
- **窗口不再有最小化按钮**，也没有交通灯。三扇窗口都是「看完就走」的，最小化本来就不在路径上；托盘菜单是它们的常驻入口。
- **双击标题条不会最大化**：`internal_toggle_maximize` 同时要求 `is_resizable` 与 `is_maximizable`，三扇窗口都设了 `maximizable(false)`，所以那条路是空转。
- 圆角一律不加。无边框窗口在 macOS 上是直角，CSS 圆角只会在四角露出桌面（要真圆角得开 `transparent`，那会把窗口拖进另一套合成路径）。直角本来就更像素。
- **Windows 侧没有真机验过**（issue #16 一起验）：`WS_THICKFRAME` 那条是从 tao 源码读出来的，把手能不能用、`start_dragging` 在 `WS_POPUP` 上的表现都要在那台机器上看一次。

## 被否决的方案

- **B（透明标题栏）**：改动最小，交互一点不动，但只有 macOS 有效。用户明确要两个平台一致。
- **D（什么都不画）**：领养窗口关掉等于退出应用，而这是用户放弃领养时唯一的出口。没有可见的关闭入口，用户会以为程序卡死了。
- **`titleBarStyle: Overlay`**：macOS 专属，且交通灯会浮在雨夜画面上 - 那三颗彩色圆点比灰条更抢眼。
- **日记页留系统标题栏**（混合方案）：能白拿系统缩放，但一个应用里两种标题栏比一种丑的更难解释。
