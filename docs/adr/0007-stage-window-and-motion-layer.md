# 0007 - 舞台窗口跟随猫，逐帧位移独立于世界层

日期：2026-07-29
状态：已采纳

## 背景

世界内核（[ADR 0001](0001-offline-catchup-simulation.md)）的状态演化只发生在 30 分钟的整步上 - 这是离线推演可回放的算术基础，不能动。
它产出的 `renderIntent.action` 因此也是 30 分钟粒度的：「猫现在想走路」。

但「走过去」是逐帧的事：位置、朝向、抵达判定都需要帧时钟。
而猫一旦走出宠物窗口，留在身后的爪印就没有画布可落 - 窗口只有 240×190。

三个需求同时压在这里：猫要能在桌面上漫游（[ADR 0004](0004-desktop-as-territory.md) 的领地）、爪印要留在猫走过的地方、以及后续要能爬到前台窗口的上边缘。

## 决策

### 一、逐帧位移放在应用层，不放进世界层

新增**运动层**（`src/app/motion.ts`），帧驱动，不进存档。

分工是：**世界层决定猫想干什么，运动层负责把它送到那里。**

- 世界层：`renderIntent.action` 给出意图（走路 / 吃饭 / 睡觉…），30 分钟粒度。
- 运动层：持有位置、朝向、速度，逐帧推进，决定当前该播哪个具体动作。

**运动层不得反向写入世界层。** 世界是状态的唯一权威，任何从帧循环回写状态的通路都会破坏离线等价性 - 补算时没有帧，那条通路不存在，两边就会算出不同结果。

位置不进存档是有意的：重启后猫出现在一个合理的位置即可，没人会记得它昨晚站在哪。

### 二、宠物窗口是一个跟随猫的「舞台」

窗口放大成一个**舞台**（约 3 倍精灵宽），容纳猫本体加身后一小段爪印。
舞台不是每帧都动 - 只在猫接近舞台边缘时才整体挪一次（带滞后），因为移动窗口比移动画布内的坐标贵得多，每帧挪还容易看出抖动。

猫的屏幕位置 = 舞台的屏幕位置 + 猫在舞台内的位置。

**爪印按屏幕坐标记录，每帧换算成舞台内坐标再画。** 这样舞台滚动时爪印留在原地不跟着飘；落在舞台外的爪印被裁掉，可以接受 - 它们在猫身后且只存活几秒，而舞台足够宽。

## 理由

**为什么不把逐帧位移塞进世界层。** 那需要世界层按帧推进位置，等于引入一个不能用 30 分钟整步回放的连续量，离线等价性当场失效。而离线等价性是「猫 24h 都在生活」这个承诺的唯一技术保证，它比架构上的整齐重要得多。

**为什么不用全屏透明窗口。** 全屏是很多桌面宠物的做法，能一次解决漫游、爪印、贴边行走。放弃它的理由有两条：一是渲染代价，全屏画布在 2x 屏上是 3840×2160×4 ≈ 33MB 的后备存储，每帧清屏与合成的填充率代价不值得为几个爪印付；二是风险面，穿透是整窗一刀切的（[ADR 0006](0006-alpha-mask-hit-testing.md)），全屏窗口意味着任何一次判定失误挡住的是整块屏幕而不是一小片。

**为什么舞台要带滞后。** 窗口位置变更是跨进程的窗口服务器操作，每帧调用既贵又可能与合成不同步产生抖动。滞后把它降到「猫走到边上才动一次」。

## 影响

- 运动层需要自己的测试（位置推进、抵达判定、舞台滚动的滞后），与世界层的缝一测试并列。它是纯逻辑，注入帧时长即可测试，不需要 DOM。
- 舞台变大意味着透明区变大，更依赖 alpha 掩膜命中测试。ADR 0006 的失效方向（判定不出来时一律穿透）因此更重要。
- 命中测试的坐标换算要跟着改：光标位置目前是「相对窗口客户区」，猫在舞台内有偏移，两者不再等同。
- 爬前台窗口（ticket #12）要把「目标是某个屏幕矩形的上沿」翻译成运动层的目标点，属于运动层的职责，世界层只需知道「猫想上高处」。
- 挂件（ticket #9）的食盆与猫窝有各自的屏幕位置，运动层需要能接受「走到某个屏幕坐标」的目标。
