# CyberCat

赛博城市里，有一只真实的猫在等你回家。

一只常驻在你桌面上的像素猫。它 24 小时都在生活，会饿、会困、会生病、会死。
你不在的时候它也在过日子，回来时它会把这段时间的事记成日记给你看。

macOS 与 Windows。没有账号，不联网，所有东西都存在你自己的电脑上。

---

## 它是什么

不是一个挂在角落里循环播放动画的挂件。它有状态，而状态跟着真实时间走：

- **关着电脑的那八个小时也算。** 下次打开时它会把这段时间补算出来 - 你会看到一只饿了的猫，日记里写着它昨晚干了什么。
- **它可以拒绝你。** 睡着的时候摸它会被甩尾巴，心情差的时候不理你的光标。
- **它会死。** 饱食度见底之后再挨饿 24 小时开始生病，生病 48 小时之后离开。这条链完整存在，不是摆设。

## 领养

第一次启动没有猫。会有一只猫从雨夜里走过来，停在你面前。

七个品种：橘猫、黑猫、奶牛猫、布偶猫、德文卷毛、美短、阿比西尼亚。
**品种差异做在结构上**，不是换个颜色 - 体型、耳朵、尾巴粗细、腿长、绒毛都不一样，德文的大耳朵和阿比的瘦长身形隔着半个屏幕也认得出。

外观由一颗 Seed 决定，所以同品种的两只猫也长得不一样，**你这一只是独一无二的**。
不想要就点「再等等」，换下一只走过来。选定之后给它起名。

性格也是随机的（活跃、亲人、贪吃、好奇），它决定这只猫多爱动、多爱追光标、被拎起来之后是跟过来蹭你还是走开趴下。

## 它自己会做的事

站着呼吸、走动、坐下、趴下、睡觉、舔毛、打哈欠、伸懒腰、扑跳、吃饭。
上面还叠着一层微动作：随机眨眼、耳朵抖动、偶尔歪头、尾巴扫地。

**它走过的地方会留下爪印**，一会儿就淡掉。

做什么取决于状态与作息：白天活跃，深夜大多在睡，饿了会去食盆边徘徊，累垮了会自己去睡。
饿到一定程度会**盖过作息** - 碗里有粮的话它会自己醒过来吃。

## 桌面就是它的领地

- **它会爬到你正在用的窗口上沿**，在那条窄边上走动、趴下。你切走或关掉那个窗口，它会跳下来。
- **它走到屏幕边缘时会自己挪窝**，不会卡在一个固定的框里。
- **猫身上可以点，其余地方点得穿。** 它趴在你的代码上，你照样能点到下面的代码。

## 你能对它做的事

| 动作 | 结果 |
|---|---|
| 点它 | 抚摸。头顶冒爱心，亲密度上升。睡着时会被拒绝 |
| 按住拖 | 把它拎起来。松手后落地，会有一小段反应 - 亲人的猫跟过来蹭你，高冷的猫走开趴下 |
| 快速来回甩光标 | 逗猫。它会扑向光标**旁边**，不压住你要点的东西 |
| 点食盆 | 添粮。吃不吃仍然由它决定 |
| 点它头顶的气泡 | 打开猫咪日记（离开够久之后才会冒） |

光标即逗猫棒，不需要任何开关。但它是**邀请而非命令**：睡着、生病、刚吃饱犯困、心情差、你正在打字、玩腻了、这一小时追够了次数、光标离得太远、光标的运动不像猎物 - 任何一条不满足，它完全无视你的光标。
所以它不会变成一个跟着鼠标乱窜的东西。

## 食盆与猫窝

两个摆在桌面上的挂件。可以横向拖动、可以在托盘里藏起来、两个位置重叠过半会自动交换。
碗里剩几份粮是看得见的（一次添两份，最多存三份）。猫要吃饭或睡觉时会自己走过去。

## 猫咪日记

它自己写的。按天分组，每条前面是时刻：什么时候吃了饭、什么时候睡了、什么时候生病了、你什么时候摸了它。
**你离开久了再回来，它头顶会冒一个气泡** - 点开就是这段时间的日记。

窗口可以拖、可以缩放（右下角），按 Esc 关掉。

## 生病、离开与档案

饱食度见底之后开始挨饿，24 小时后生病（**只有这一级会发系统通知**），生病 48 小时后离开。
生病期间托盘里会出现「喂药」。

它离开之后有一页告别：它活着时的样子、陪了你多少天、它这一生的日记。
**所有养过的猫都在档案里**，不会被新猫覆盖。可以随时再领养一只，没有任何惩罚。

## 托盘

菜单栏（macOS）或任务栏（Windows）里那只猫头是全部常驻入口。

- **图标本身反映状态**：正常、睡着、饿了、生病、已离开。而且是**你这只猫的品种配色**画的
- 状态摘要一行 + 四条详情：饱食度、精力、心情、亲密度
- 猫咪日记、喂食、喂药（仅生病时）、告别与档案
- 桌面挂件：食盆、猫窝的显示开关
- **安静模式**：猫只趴着休息，不响应光标、不爬窗口、不闲逛。跨重启保持
- 退出

## 它不会做的事

这几条是刻意的边界：

- **不拦你的键盘和鼠标。** 挡视线可以，挡操作不行。
- **不推你的桌面图标。** 猫感十足，但用户第一反应是文件丢了。
- **默认静音。**
- **只有生病发通知。** 饿了不发 - 不然陪伴就变成催促。
- **全屏和投屏时它自己消失。** 你在看片或者做演示，它不该出现在画面里；退出之后自己回来。

## 安装

### macOS

下载 `CyberCat_x.y.z_universal.dmg`（同一个包同时支持 Apple Silicon 与 Intel），拖进「应用程序」。

包**没有签名和公证**，所以第一次打开要绕一下 Gatekeeper：在「应用程序」里右键点它 → 打开 → 再点一次「打开」。
或者去「系统设置 → 隐私与安全性」点「仍要打开」。

打开之后**不会出现在程序坞里**，它只在菜单栏。领养的时候会临时出现，选完就退回菜单栏。

### Windows

下载 `.msi` 或 `.exe`（NSIS）安装包，双击安装。

需要 **WebView2 运行时**。Windows 11 自带；Windows 10 上如果没有，安装包会自己下载安装。

> Windows 版还没有在真机上完成验收，见下面的「已知限制」。

## 存档在哪

- macOS：`~/Library/Application Support/app.cybercat.pet/`
- Windows：`%APPDATA%\app.cybercat.pet\`

| 文件 | 内容 |
|---|---|
| `world.json` | 当前这只猫：身份、四条需求、日记 |
| `memorial.json` | 所有养过的猫的档案。**这份丢了就再也回不来** |
| `props.json` | 食盆与猫窝的位置 |
| `settings.json` | 安静模式等开关 |

删掉 `world.json` 会重新走领养流程（档案里的旧猫不受影响）。
想备份一只猫，复制整个目录就行。

## 让 GitHub 帮你构建

`.github/workflows/build.yml` 有一个两平台的矩阵：macOS 出 universal DMG，Windows 出 MSI 与 NSIS。
两个平台的包**必须各自在对应系统上构建**，不能交叉编译，所以是矩阵而不是一台机器出两份。

- **要一份包拿去装**：Actions 页面 → build → Run workflow。产物挂在那次运行的 artifact 里，保留 30 天。**不会产生任何 Release。**
- **要正式发一版**：把 `src-tauri/tauri.conf.json` 的 `version` 改好，提交，然后打 tag 推上去：

  ```bash
  git tag v0.1.0 && git push origin v0.1.0
  ```

  这会建一个**草稿 Release** 并把两个平台的安装包挂上去。草稿是刻意的 - 发布之前你还得在 macOS 与 Windows 上各装一次。

- push 到 main 只跑测试与类型检查，不构建 - macOS runner 按 10 倍计费，没必要每次提交都烧两台机器。

签名是可选的：仓库里配了 `APPLE_CERTIFICATE` 等 secret 之后，同一个 workflow 会自动签名并公证，不用改任何配置。没配就是 ad-hoc 签名的包。

## 自己构建

### 两个平台都需要

- **Node.js 20+**（开发用的是 26）
- **Rust 1.77.2+**（开发用的是 1.97）

```bash
npm install
npm run app:dev      # 开发模式跑起来
npm run app:build    # 打出安装包
```

### macOS

再装 Xcode 命令行工具：

```bash
xcode-select --install
```

产物：

- `src-tauri/target/release/bundle/dmg/CyberCat_x.y.z_aarch64.dmg`
- `src-tauri/target/release/bundle/macos/CyberCat.app`

要出**同时支持 Apple Silicon 与 Intel** 的那一个包（CI 出的就是它）：

```bash
rustup target add x86_64-apple-darwin aarch64-apple-darwin
npm run tauri build -- --target universal-apple-darwin
# → src-tauri/target/universal-apple-darwin/release/bundle/dmg/CyberCat_x.y.z_universal.dmg
```

要产出**签名并公证**的 DMG，构建前设好这几个环境变量（需要 Apple Developer 账号）：

```bash
export APPLE_SIGNING_IDENTITY="Developer ID Application: 你的名字 (TEAMID)"
export APPLE_ID="你的 Apple ID"
export APPLE_PASSWORD="应用专用密码"
export APPLE_TEAM_ID="TEAMID"
npm run app:build
```

不设的话产出的是 ad-hoc 签名的包，拿到的人要手动绕 Gatekeeper。

### Windows

需要：

- **Visual Studio 生成工具**，含 MSVC v143 与 Windows SDK
- Rust 的 `x86_64-pc-windows-msvc` 目标（`rustup` 装完默认就是）
- WebView2 SDK 由 Cargo 自动拉，不用单独装

```powershell
npm install
npm run app:build
```

产物：

- `src-tauri\target\release\bundle\msi\CyberCat_x.y.z_x64_en-US.msi`
- `src-tauri\target\release\bundle\nsis\CyberCat_x.y.z_x64-setup.exe`

**不能交叉编译。** Windows 的包必须在 Windows 上构建（MSVC 工具链与资源编译器都不在别的系统上跑）。
在 macOS 上能做的只有类型检查：

```bash
npm run check:win    # cargo check --target x86_64-pc-windows-msvc
```

它能查出 Windows 分支的编译错误，但不链接，也检查不出运行时行为。

### 其他命令

```bash
npm test             # 全套测试
npm run typecheck    # TypeScript 类型检查
npm run harness      # 渲染核心的人工验证页：每个品种 × 每个动作
```

## 已知限制

- **Windows 版尚未真机验收。** 两个平台的代码都写了，macOS 侧全部在真机上验过；Windows 侧的透明窗口、DPI 换算、全屏检测、托盘图标缩放都只做过类型检查。
- **最大化的窗口爬不上去。** 猫要停在某条边上，需要那条边上方留出空间，而最大化窗口的上沿已经贴着屏幕顶部。表现是「它不去」，不会浮空或者被裁掉。
- **换动作的瞬间高度是硬切的**，不是平滑过渡。
- **单显示器。** 猫不会跨屏漫游。
- **macOS 的包未签名未公证。**

## 技术

Tauri v2 + Rust + TypeScript。没有游戏引擎，没有精灵图。

猫的每一个像素都是程序画出来的：品种参数 + Seed 驱动的逐像素光栅化，姿态与动作全部由代码生成，所以七个品种 × 十几个动作 × 无数颗 Seed 都不占一张贴图。

状态演化是一个纯函数，不读时钟也不读随机数发生器的当前值 - 这既是「关机八小时也算」能精确补算出来的原因，也是它能被完整测试的原因。

不联网，不上传任何东西，没有遥测。
